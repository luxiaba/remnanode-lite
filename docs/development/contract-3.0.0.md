# Remnawave Node 3.0.0 Behavioral Contract Baseline

[Back to the development guide](README.md)

This document records the compatibility baseline for official Remnawave Node
`3.0.0`. The previous [2.8.0 baseline](contract-2.8.0.md) remains an immutable
historical record; this page describes the reviewed delta and the behavior
implemented by Remnanode Lite.

## Reviewed Upstream Delta

Official `3.0.0` contains eight commits after `2.8.0`. Most of the source diff
migrates the official TypeScript build from Webpack to Rspack, reorganizes
imports, and updates internal dependencies. Those changes do not alter the Go
implementation or its compatibility surface.

The compatibility-relevant changes are:

- Zod `3.25.76` to `4.4.3`;
- `@remnawave/node-plugins` `0.4.5` to `0.6.0`;
- the plugin `preStart.cleanupSockets` stage;
- the official image's Xray Core selection from `v26.6.27` to `v26.7.28`.

There are no new Node environment variables. The 26 public `/node` routes and
two internal routes retain the same methods, paths, request fields, response
fields, and nesting as `2.8.0`.

## Pre-Start Socket Cleanup

Panel may include this plugin configuration:

```json
{
  "preStart": {
    "enabled": true,
    "cleanupSockets": {
      "enabled": true,
      "files": ["/dev/shm/*.sock"]
    }
  }
}
```

The Panel introduced the configuration field that emits this stage in release
`3.1.0`. Release `3.0.0` can use Node `3.0.0`, but does not send
`preStart.cleanupSockets`.

`preStart.enabled` defaults to `false`. `cleanupSockets` is optional; when it
is present, `enabled` and `files` are required. The list accepts at most 64
absolute paths or glob patterns. Each path is trimmed, must remain non-empty,
and must not contain a NUL byte. The official `*`, `?`, and bracket-pattern
forms are supported.

The Xray lifecycle order is:

```text
confirm previous core stopped
  -> expand configured patterns
  -> remove matching Unix sockets
  -> start replacement core
```

Each pattern processes at most 256 matches. `lstat` is used so regular files,
directories, and symbolic links are never followed or removed. Missing paths
are ignored. Expansion, inspection, or removal failures are logged and do not
prevent rw-core from starting. Cleanup runs only before an actual process
spawn; an unchanged start request that reuses the running core does not run it.

The Panel and its plugin configuration are trusted administrative inputs. A
broad pattern can remove another process's Unix socket if that process shares
the same filesystem and permissions. Operators should use precise paths in a
Node-owned runtime directory. Remnanode Lite intentionally does not add a
project-specific allowlist or socket-activity probe that would diverge from the
official behavior.

## Zod 4 Acceptance Boundaries

Normal values generated by Panel are unchanged. The reviewed boundary changes
are narrow:

- UUID fields accept RFC UUID versions 1 through 8 with an RFC variant, plus
  the nil UUID and lowercase all-`f` maximum UUID. Other version/variant forms
  and uppercase all-`F` are rejected.
- Scoped IPv6 text such as `fe80::1%eth0` is rejected by the Zod 4 IP schemas.
- `z.int()` values must be JavaScript safe integers. Plugin integer fields are
  therefore limited to `[-9007199254740991, 9007199254740991]` before their
  field-specific minimum or maximum is applied.

Remnanode Lite preserves the established HTTP 400 validation envelope. It does
not copy Zod 4's complete internal issue wording or nested error metadata,
because Panel depends on the response contract rather than the official
implementation's library-specific diagnostics.

## Runtime Selection

The release runtime lock selects Xray Core `v26.7.28`, commit
`5ca6f4b7d4dc20a881d4330e498892697627ec0c`, for both supported architectures.
GeoIP and GeoSite are refreshed with exact source archives and payload digests;
the ASN database remains at its existing pinned source. Docker and Native
bundles consume the same lock and verify every asset before packaging.

The runtime update is release packaging, not a new Panel API. Exact versions,
sizes, hashes, licenses, and source links live in
`release/runtime-assets.lock.json` and the generated bundle notices.

rw-core `v26.7.28` also changes the REALITY compatibility default. When an
inbound omits `minClientVer`, the core uses `26.3.27`; older Xray-based and
third-party clients may be rejected even though the configuration starts.
Updating clients is the preferred response. Setting `minClientVer` explicitly
to `0.0.0` restores the older compatibility boundary, but rw-core warns that
this can increase blocking risk. Remnanode Lite keeps the upstream behavior and
does not rewrite Panel configuration.

## Accepted Implementation Differences

The accepted differences already documented for `2.8.0` remain unless this
page overrides them. In particular, Remnanode Lite is one Go process rather
than the official Node.js and s6 layout, retains only compact post-start Xray
state for the 512 MiB target, and implements the public behavior without
copying NestJS, CQRS, Rspack, or Zod internals.

Socket glob expansion uses Go's standard library and truncates the returned
matches to the official 256-entry processing limit. Unlike the official
asynchronous iterator, the standard library constructs the match slice before
truncation. A trusted administrator would need to configure an unusually broad
pattern over a very large directory for this to matter. The risk is accepted
to keep the implementation dependency-free and easy to audit.

Two existing plugin-validation differences remain intentionally narrow. A
negative `torrentBlocker.blockDuration` is rejected because it has no defined
operational meaning, although the external package's bare `z.int()` accepts it.
Go's CIDR parser accepts a zero-padded prefix length such as `/024`, while Zod 4
rejects that spelling. Panel does not generate either form, so changing the
production parser would add complexity without improving normal operation.

## Verification

Source-level verification:

```bash
export REMNANODE_OFFICIAL_SOURCE=/absolute/path/to/remnawave-node-3.0.0
go run ./cmd/contract-source-check -source "$REMNANODE_OFFICIAL_SOURCE"
go test -count=1 ./internal/contract ./internal/nodeapi ./internal/plugin ./internal/xray
```

Release acceptance additionally requires the immutable `sha-<commit>`
candidate to connect to a compatible real Panel, start the bundled rw-core,
and carry real proxy traffic. An acceptance run using a release with pre-start
support (`3.1.0` or newer) must also exercise one stale-socket cleanup without
deleting a regular file. Host details, logs, traffic records, and server data remain
outside the repository.
